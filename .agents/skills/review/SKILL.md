# /review — Review & Verify

Use this skill after implementation to catch bugs, convention violations, and unverified claims.

## Steps
1. **Audit the diff**: Check logic correctness, edge cases, error handling, duplication, and adherence to repo conventions.
2. **Run real checks**: Execute the relevant test suite, linter, or build command after the final edit.
3. **Report truthfully**: State only directly observed results, exact scope, and any failures—never extrapolate or claim unrun checks passed.
